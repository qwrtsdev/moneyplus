# MoneyPlus — Codebase Structure

This document explains how the app is put together: every folder, every
file, and every third-party piece it depends on — what each one is, why
it's there, and how it actually works under the hood. It's written for
someone who knows how to code but isn't necessarily familiar with Flutter,
Dart, or the specific libraries used here.

## Tech stack at a glance

| Piece | What it is |
|---|---|
| [Flutter](https://flutter.dev) | The UI framework/SDK this whole app is built with — compiles one Dart codebase to Android, iOS, Linux, macOS, Windows, and web. |
| [Dart](https://dart.dev) | The programming language Flutter apps are written in. |
| [go_router](https://pub.dev/packages/go_router) | Screen-to-screen navigation (routing), described further down. |
| [google_fonts](https://pub.dev/packages/google_fonts) | Loads the **Noto Sans Thai** typeface used everywhere in the app. |
| [phosphoricons_flutter](https://pub.dev/packages/phosphoricons_flutter) | The icon set used in the bottom nav bar. |

Notably absent: **Material Design** (Flutter's built-in Google-style
component library) and **Cupertino** (its iOS-style equivalent). More on
that below — it's a deliberate choice, not a missing dependency.

## Folder layout

```
lib/
├── main.dart                       # App entry point (WidgetsApp.router)
└── src/
    ├── routing/
    │   └── app_router.dart         # go_router configuration
    ├── theme/
    │   ├── app_colors.dart         # Monochrome color tokens
    │   ├── app_typography.dart     # Noto Sans Thai text styles
    │   └── app_radius.dart         # Corner-radius tokens
    ├── widgets/
    │   ├── scaffold_with_nav_bar.dart  # Shell that hosts the bottom bar
    │   ├── bottom_nav_bar.dart         # The flat bottom bar itself
    │   └── app_page.dart               # Page background + safe-area shell
    └── screens/
        ├── home_screen.dart         # หน้าหลัก — placeholder
        ├── finance_screen.dart      # การเงิน — placeholder
        ├── balance_screen.dart      # สมดุลเงิน — placeholder
        ├── split_bill_screen.dart   # หารบิล — placeholder
        └── settings_screen.dart     # ตั้งค่า — placeholder
```

Each screen is currently a bare placeholder: `AppPage` (full-bleed
background) wrapping a centered `Text` body — no cards, lists, titles, or
private sub-widgets. That's the starting point for building out real screen
content later; the navigation, theming, and nav bar around it are already
done.

`main.dart` is the only file that composes the app together (typography +
router); everything under `lib/src/` is implementation detail it pulls in.

### Import convention

Dart has no bundler-style `@/` path alias like JavaScript/TypeScript
tooling. Instead of relative imports (`../../theme/app_colors.dart`,
`../theme/app_colors.dart`), every file in this project imports its own
sibling files via the **package URI**:

```dart
import 'package:moneyplus/src/theme/app_colors.dart';
```

This resolves the same regardless of how deeply nested the importing file
is — root-relative, like `@/` would be — and is the Dart-idiomatic way to
avoid `../../../` chains. `moneyplus` here is the package `name:` declared
in `pubspec.yaml`; Dart's package resolver (via `.dart_tool/package_config.json`,
generated by `flutter pub get`) maps that prefix back to this project's own
`lib/` folder, so `package:moneyplus/src/...` always points inside this
repo (as opposed to `package:go_router/...`, which resolves to the
installed `go_router` dependency instead).

## The app entry point — `main.dart`

```dart
void main() {
  runApp(const MainApp());
}
```

`runApp` is Flutter's bootstrap call: it takes a widget and attaches it as
the root of the entire UI tree, then starts the rendering/event loop. Every
Flutter app starts this way.

`MainApp` builds a [`WidgetsApp`](https://api.flutter.dev/flutter/widgets/WidgetsApp-class.html):

```dart
WidgetsApp.router(
  title: 'MoneyPlus',
  color: AppColors.ink,
  debugShowCheckedModeBanner: false,
  textStyle: AppTypography.body,
  routerConfig: appRouter,
)
```

Most Flutter tutorials start from `MaterialApp` instead. `WidgetsApp` is
what `MaterialApp` itself is built on top of — it provides the
framework-level plumbing every Flutter app needs (a `Navigator`, `MediaQuery`,
`Directionality`, localization, focus handling) **without** any Material
Design visuals or components layered on top. `MaterialApp` = `WidgetsApp` +
Material's theme system, `Scaffold`, `Icons`, ripple effects, etc.
`CupertinoApp` = `WidgetsApp` + Apple's iOS-style equivalents. This app uses
plain `WidgetsApp` because it wants neither.

What each constructor argument does:

- **`color`** — used by the OS on platforms that show a colored app
  entry (e.g. Android's recent-apps task switcher strip). Cosmetic, not
  visible inside the app itself.
- **`textStyle`** — the default `TextStyle` every `Text` widget in the app
  inherits unless it specifies its own (via Flutter's `DefaultTextStyle`
  ambient/inherited widget). Set to `AppTypography.body` so Noto Sans Thai
  is the baseline font everywhere without every screen having to say so.
- **`routerConfig`** — hands the whole app over to go_router (see below).
  `WidgetsApp.router` (the `.router` named constructor) accepts the exact
  same `routerConfig` parameter `MaterialApp.router` does, which is why
  swapping from `MaterialApp` to `WidgetsApp` didn't require changing the
  routing code at all.

## Why there's no Material Design

This is the app's one unusual, deliberate constraint: it does not use
Flutter's Material widget library at all — no `Scaffold`, no `AppBar`, no
`Icons`, no `ColorScheme`, no `MaterialApp`, no ripple effects. Concretely,
enforced in a few places:

- `main.dart` runs `WidgetsApp.router`, not `MaterialApp.router` (explained
  above).
- `app_router.dart` gives every `GoRoute` a `pageBuilder` returning
  [`NoTransitionPage`](https://pub.dev/documentation/go_router/latest/go_router/NoTransitionPage-class.html)
  instead of the shorthand `builder:` parameter. go_router's `builder:`
  quietly wraps whatever widget you return in a Material `MaterialPage`
  under the hood — using `pageBuilder:` with `NoTransitionPage` (a plain,
  Material-free `Page` subclass that go_router itself provides) avoids that.
- Icons come from `phosphoricons_flutter` instead of Material's built-in
  `Icons` font (see the icons section below), rendered through the plain
  `Icon` widget from `package:flutter/widgets.dart` — `Icon` itself isn't
  Material-specific, only the `Icons` *data* (the icon glyphs) bundled with
  Material is.
- `pubspec.yaml` sets `uses-material-design: false`, which stops Flutter
  from bundling the Material icon font asset into the app at all (a real,
  if small, binary-size saving).
- Every file in `lib/` imports `package:flutter/widgets.dart` — never
  `package:flutter/material.dart` or `package:flutter/cupertino.dart`. You
  can verify this at any time with:
  ```sh
  grep -rn "package:flutter/material.dart\|package:flutter/cupertino.dart" lib/
  ```
  which should print nothing.

Because there's no Material `Theme`/`Scaffold` to lean on, a few small
custom widgets stand in for what they'd normally provide — see "Widgets"
below.

## Design system — `lib/src/theme/`

Material apps get colors and text styles for free from `ThemeData` /
`ColorScheme`. Without Material, this app defines its own equivalent as
three small files of plain Dart constants:

### `app_colors.dart` — the palette

```dart
abstract class AppColors {
  static const ink = Color(0xFF111111);      // near-black — text, icons, indicator
  static const paper = Color(0xFFFFFFFF);    // white — page/backgrounds
  static const muted = Color(0xFF8A8A8A);    // gray — inactive nav icons/labels
  static const divider = Color(0xFFE4E4E4);  // hairline gray — the nav bar's top border
  static const surface = Color(0xFFF6F6F6);  // very light gray — reserved for future card backgrounds
}
```

Five colors, full stop — no accent color, no dark-mode variant. The app is
a fixed black-on-white design by choice, so there's no `ColorScheme` or
theme-switching logic to build. `Color(0xFF111111)` is Flutter's standard
color literal: `0xAARRGGBB` in hex — `FF` alpha (fully opaque) followed by
the `11 11 11` RGB value.

### `app_typography.dart` — text styles

```dart
static TextStyle get body => GoogleFonts.notoSansThai(
      fontSize: 15,
      color: AppColors.ink,
      height: 1.4,
    );
```

`GoogleFonts.notoSansThai(...)` comes from the `google_fonts` package (see
the dependencies section) and returns a Flutter `TextStyle` using the Noto
Sans Thai typeface at whatever size/weight/color you pass in — it's a thin
wrapper around `TextStyle` itself, not a separate styling system.

These are plain **static getters** on an `abstract class` — not a Material
`TextTheme` extension — because there's no ambient `Theme` widget in the
tree to attach a theme extension to. `AppTypography.body`,
`AppTypography.navLabel`, and `AppTypography.navLabelActive` are just
referenced directly wherever a `Text` widget needs one, e.g.
`Text('...', style: AppTypography.body)`. `navLabelActive` is defined as
`navLabel.copyWith(color: AppColors.ink, fontWeight: FontWeight.w700)` —
`copyWith` returns a new `TextStyle` with only the given fields overridden,
so the active nav label always stays in sync with the inactive one's font
size/family and only differs in color/weight.

### `app_radius.dart` — corner rounding

```dart
abstract class AppRadius {
  static const double indicator = 2;
}
```

Just one token right now, for the nav bar's active-tab underline (a nearly
square-cornered pill, 2px of rounding). The design is intentionally flat
and hairline-bordered rather than the heavily rounded shapes Material
Design defaults to, so there isn't a large radius scale to define.

## Routing — `lib/src/routing/app_router.dart`

### What go_router is

Flutter's built-in `Navigator` manages navigation as an explicit stack you
push/pop widgets onto imperatively (`Navigator.push(...)`). **go_router**
sits on top of it and lets you describe navigation **declaratively** — as a
static tree of URL-like paths mapped to screens — and then navigate by URL
(`context.go('/finance')`) instead of manually managing push/pop calls. It
also gives every screen a real, inspectable path (`/`, `/finance`,
`/split-bill`, ...), which is what makes deep-linking and browser-style
back/forward behavior possible for free, and is why it's the most widely
used routing package in the Flutter ecosystem (it's semi-official — maintained
by the Flutter team itself).

### How this app's routes are structured

```dart
final GoRouter appRouter = GoRouter(
  initialLocation: AppRoutes.home,
  routes: [
    StatefulShellRoute.indexedStack(
      builder: (context, state, navigationShell) =>
          ScaffoldWithNavBar(navigationShell: navigationShell),
      branches: [
        StatefulShellBranch(routes: [GoRoute(path: '/', pageBuilder: ...)]),          // หน้าหลัก
        StatefulShellBranch(routes: [GoRoute(path: '/finance', pageBuilder: ...)]),   // การเงิน
        StatefulShellBranch(routes: [GoRoute(path: '/balance', pageBuilder: ...)]),   // สมดุลเงิน
        StatefulShellBranch(routes: [GoRoute(path: '/split-bill', pageBuilder: ...)]),// หารบิล
        StatefulShellBranch(routes: [GoRoute(path: '/settings', pageBuilder: ...)]),  // ตั้งค่า
      ],
    ),
  ],
);
```

- **`GoRoute`** — one path-to-screen mapping. Its `pageBuilder` receives the
  routing `context`/`state` and returns a go_router `Page` object; here
  every route wraps its screen in `NoTransitionPage` (see the Material
  section above for why not the default `builder:`/`MaterialPage`).
- **`StatefulShellBranch`** — one independent navigation "branch" — in this
  app, one bottom-nav tab. Each branch has its own nested `Navigator` and
  its own back-stack, kept alive independently of the other branches.
- **[`StatefulShellRoute.indexedStack`](https://pub.dev/documentation/go_router/latest/go_router/StatefulShellRoute/StatefulShellRoute.indexedStack.html)**
  — wraps all 5 branches in a single Flutter
  [`IndexedStack`](https://api.flutter.dev/flutter/widgets/IndexedStack-class.html),
  which builds *all* branches' widget trees up front but only paints the
  active one. This is why switching tabs doesn't rebuild the screen you
  were on or lose its scroll position — the inactive tabs are still alive,
  just not visible. That's the standard, recommended go_router pattern for
  a bottom-nav app; it's also more memory-hungry than lazily building each
  tab on first visit, which is an acceptable trade-off at this app's size.
- **`builder: (context, state, navigationShell) => ScaffoldWithNavBar(...)`**
  — the `StatefulShellRoute`'s own builder wraps whichever branch is
  currently active in `ScaffoldWithNavBar` (see below), so the bottom nav
  bar is always on screen around the active tab's content.

`AppRoutes` (top of the file) is just a set of `static const` path strings
(`AppRoutes.home = '/'`, etc.) so the path for each tab is defined exactly
once and referenced everywhere else — screens, the router, and (indirectly)
the nav bar never hardcode a route string.

**Branch order must match `ScaffoldWithNavBar._items` order.** Tapping nav
item index `i` calls `navigationShell.goBranch(i)` — a plain integer index,
not a path — so the Nth `StatefulShellBranch` here has to correspond to the
Nth `BottomNavItem` in `ScaffoldWithNavBar`. Two branches accidentally
pointing at the same path, or branches listed in a different order than the
nav items, is exactly what caused a routing crash earlier in this project
(go_router refuses to start with a duplicate route path).

To add a 6th tab: add a `StatefulShellBranch` (with a `pageBuilder`, not
`builder`) at the matching position, a `BottomNavItem` in
`ScaffoldWithNavBar._items` at the same position, and a screen file.

## Widgets — `lib/src/widgets/`

### `AppPage` — the `Scaffold` replacement

```dart
class AppPage extends StatelessWidget {
  const AppPage({super.key, required this.body});
  final Widget body;

  @override
  Widget build(BuildContext context) {
    return ColoredBox(
      color: AppColors.paper,
      child: SafeArea(bottom: false, child: body),
    );
  }
}
```

Every screen wraps its content in this instead of Material's `Scaffold`.
`ColoredBox` paints the white background; `SafeArea` pads its child away
from OS chrome (notches, status bars, home-indicator gesture areas) —
`bottom: false` because the bottom edge is already handled by
`BottomNavBar`'s own `SafeArea` (padding it twice would double the gap).
There's no title bar — screens render their own content with nothing above
it, by design.

### `ScaffoldWithNavBar` — the tab shell

```dart
Widget build(BuildContext context) {
  return ColoredBox(
    color: AppColors.paper,
    child: Column(
      children: [
        Expanded(child: navigationShell),
        BottomNavBar(
          items: _items,
          currentIndex: navigationShell.currentIndex,
          onTap: (index) => navigationShell.goBranch(
            index,
            initialLocation: index == navigationShell.currentIndex,
          ),
        ),
      ],
    ),
  );
}
```

This is the `builder` the `StatefulShellRoute` calls, so it wraps *every*
tab. `navigationShell` is go_router's handle to the currently active
branch — putting it in `Expanded` makes it fill all remaining vertical
space above the nav bar. `navigationShell.currentIndex` tells the nav bar
which item is active; `navigationShell.goBranch(index)` is how tapping a
nav item actually switches tabs. The `initialLocation:` argument matters:
when you tap the tab you're *already on*, passing
`initialLocation: index == navigationShell.currentIndex` (i.e. `true`) resets
that branch back to its start route instead of leaving it wherever you'd
navigated to within it — the common "tap home to go home" behavior.

`_items` is the single list of `BottomNavItem`s (icon pair + Thai label)
for all 5 tabs, in the exact order the router branches are declared.

### `BottomNavBar` — the flat bottom bar

A flat, full-width bar flush with the screen edge — no pill shape, no
floating card, no Material `BottomNavigationBar` widget. It replaced an
earlier frosted-glass floating-pill design.

```dart
DecoratedBox(
  decoration: const BoxDecoration(
    color: AppColors.paper,
    border: Border(top: BorderSide(color: AppColors.divider)),
  ),
  child: SafeArea(
    top: false,
    child: SizedBox(height: 72, child: Row(...)),
  ),
)
```

A 1px hairline top border (`AppColors.divider`) separates it from page
content — no drop shadow, no elevation, consistent with the flat/hairline
aesthetic. Each of the 5 tabs is an `Expanded` `_BottomNavButton`, so they
always split the width evenly regardless of screen size.

Inside each `_BottomNavButton`, the active/inactive states are built from a
few small Flutter animation primitives rather than any Material ripple or
transition:

- **`AnimatedScale`** — scales the whole button down to `0.92` while
  pressed (tracked via `GestureDetector`'s `onTapDown`/`onTapUp`/
  `onTapCancel` callbacks toggling a `_pressed` boolean in `State`), giving
  tactile press feedback without Material's `InkWell` ripple.
- **`AnimatedContainer`** (the underline) — animates its `width` between
  `0` (inactive) and `18` (active) over 200ms whenever `selected` flips,
  producing the little underline "growing in" under the active tab.
- **The icon itself swaps `IconData`** between `widget.item.icon` (outline/
  regular weight) and `widget.item.activeIcon` (filled weight) based on
  `selected` — see the icons section below for what that weight pair means.
- **`AnimatedDefaultTextStyle`** — smoothly animates the label's `TextStyle`
  (color + font weight) between `AppTypography.navLabel` and
  `AppTypography.navLabelActive` as selection changes, instead of an
  instant jump.

All of these (`AnimatedScale`, `AnimatedContainer`, `AnimatedDefaultTextStyle`,
`GestureDetector`) are plain Flutter widgets from `package:flutter/widgets.dart` —
none of them are Material-specific; Material apps use them too, they're
just usually hidden inside higher-level Material components like `InkWell`.

## Icons — Phosphor Icons

[Phosphor Icons](https://phosphoricons.com) is a general-purpose icon
family (1,500+ icons) distributed for Flutter as the
[`phosphoricons_flutter`](https://pub.dev/packages/phosphoricons_flutter)
package — chosen specifically because it ships **multiple weights per
icon** (thin, light, regular, bold, **fill**, duotone), exposed as separate
classes: `PhosphorIconsRegular.houseSimple`, `PhosphorIconsFill.houseSimple`,
etc. Each is a plain Flutter `IconData` (the same type `Icons.home` from
Material is), so they render through the ordinary `Icon` widget — nothing
Phosphor-specific needed at the call site:

```dart
Icon(selected ? widget.item.activeIcon : widget.item.icon, ...)
```

That regular/fill pair is exactly what the nav bar's outline-vs-filled
active-state pattern is built on (`BottomNavItem.icon` = regular,
`BottomNavItem.activeIcon` = fill), defined once per tab in
`ScaffoldWithNavBar._items`:

```dart
BottomNavItem(
  icon: PhosphorIconsRegular.houseSimple,
  activeIcon: PhosphorIconsFill.houseSimple,
  label: 'หน้าหลัก',
),
```

## Dependencies

| Package | What it is | Why it's here |
|---|---|---|
| [`go_router`](https://pub.dev/packages/go_router) | Declarative, URL-based routing for Flutter, maintained by the Flutter team | Powers all navigation and the stateful bottom-nav tab shell (see Routing above) |
| [`google_fonts`](https://pub.dev/packages/google_fonts) | Programmatic access to every typeface on [fonts.google.com](https://fonts.google.com) as Flutter `TextStyle`s | Loads **Noto Sans Thai**, the app's base typeface, without manually bundling font files |
| [`phosphoricons_flutter`](https://pub.dev/packages/phosphoricons_flutter) | The [Phosphor Icons](https://phosphoricons.com) icon family as Flutter `IconData` constants | Regular/fill icon pairs for the nav bar, without relying on Material's `Icons` font |

**How `google_fonts` actually works:** by default it fetches the requested
font file over the network the first time it's used and caches it on-device
for subsequent runs — so the first launch needs network access to render
Noto Sans Thai correctly, and it's offline after that. (It can instead be
configured to bundle font files as build-time assets if offline-first-launch
matters later; this project hasn't needed that yet.)

**Why `go_router` is pinned to `>=17.5.0 <18.0.0`:** version 18 pulls in new
`material_ui`/`cupertino_ui` packages (part of Flutter's ongoing effort to
split Material/Cupertino widget code out of the core SDK into separate pub
packages) that don't compile against this project's pinned Flutter SDK
build. The last stable 17.x line has no such dependency and builds cleanly,
so it's pinned there until the SDK/package skew resolves itself upstream.

## Common tasks

**Add a 6th tab** — see the "Routing" section above: a matching
`StatefulShellBranch` + `GoRoute` in `app_router.dart`, a `BottomNavItem` in
`ScaffoldWithNavBar._items` at the same position, and a new screen file
under `screens/`.

**Change a color** — edit the relevant constant in `app_colors.dart`; every
usage (`AppColors.ink`, etc.) picks it up automatically since they're all
references to the same constant, not copies.

**Add a new text style** — add a static getter to `AppTypography` following
the existing `body`/`navLabel` pattern, built on `GoogleFonts.notoSansThai(...)`.

**Verify the no-Material constraint still holds** after making changes:

```sh
flutter analyze
grep -rn "package:flutter/material.dart\|package:flutter/cupertino.dart" lib/
```

The first should report no issues; the second should print nothing.
